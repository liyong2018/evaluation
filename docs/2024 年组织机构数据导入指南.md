# 2024 年组织机构数据导入指南

## 概述

本功能用于从 2024 年 GeoJSON 文件导入乡镇组织机构数据，支持两种方式：
1. **直接导入**：通过程序直接写入数据库
2. **SQL 脚本**：生成 SQL 脚本文件，通过 SQL 直接插入到数据库

## 文件结构

2024 年 GeoJSON 文件包含以下关键字段：

| 字段名 | 说明 | 示例 |
|--------|------|------|
| `code` | 行政区划代码 | `511902008` |
| `dwmc` | 单位（乡镇）名称 | `奇章街道` |
| `dzsheng` | 省名称 | `四川省` |
| `dzshi` | 市名称 | `巴中市` |
| `dzxian` | 县名称 | `巴州区` |
| `dzxiang` | 乡镇名称 | `奇章街道` |
| `fxpc_xzqhbma_sjgl` | 行政区划编码省 | `51` |
| `fxpc_xzqhbmb_sjgl` | 行政区划编码市 | `5119` |
| `fxpc_xzqhbmc_sjgl` | 行政区划编码县 | `511902` |
| `fxpc_xzqhbmd_sjgl` | 行政区划编码乡 | `511902008` |

## 使用方式

### 方式一：直接导入数据库

运行测试方法：

```bash
# 在项目根目录运行
mvn test -Dtest=OrganizationImportServiceTest#testImport2024Townships
```

或者在 IDE 中直接运行测试方法 `testImport2024Townships()`。

### 方式二：生成 SQL 脚本文件

运行测试方法生成 SQL 脚本：

```bash
# 在项目根目录运行
mvn test -Dtest=OrganizationImportServiceTest#testGenerate2024TownshipChangeSql
```

SQL 文件将保存到 `docs/organization_2024_change.sql`

### 方式三：通过 API 接口导入

**直接导入：**
```bash
POST /api/organization-import/import-2024-townships
Content-Type: application/x-www-form-urlencoded

filePath=frontend/public/zzjg/2024-xzjznl-example.geojson&year=2024
```

**生成 SQL 脚本：**
```bash
POST /api/organization-import/generate-sql
Content-Type: application/x-www-form-urlencoded

filePath=frontend/public/zzjg/2024-xzjznl-example.geojson&year=2024
```

**下载 SQL 脚本文件：**
```bash
GET /api/organization-import/download-sql?filePath=frontend/public/zzjg/2024-xzjznl-example.geojson&year=2024
```

## SQL 脚本说明

生成的 SQL 脚本包含以下部分：

### 第一部分：备份 2020 年基准数据

```sql
-- 备份 organization 表中的 2020 年乡镇数据
-- mysqldump -u 用户名 -p 数据库名 organization --where="year=2020 AND level=4" > backup_organization_2020_township.sql
```

**建议在执行变更前先备份数据：**
```bash
# 备份 organization 表
mysqldump -u root -p evaluation organization --where="year=2020 AND level=4" > backup_organization_2020_township.sql

# 备份 grassroots_organization 表
mysqldump -u root -p evaluation grassroots_organization --where="year=2020 AND level=4" > backup_grassroots_organization_2020_township.sql
```

### 第二部分：数据变更 SQL

#### 2.1 新增数据
```sql
-- 新增：511902009 - 新增街道
INSERT INTO `organization` (`parent_id`, `code`, `name`, `level`, `year`, `province_name`, `city_name`, `county_name`, `township_name`, `is_baseline`, `is_deleted`, `create_time`, `update_time`) VALUES
  (NULL, '511902009', '新增街道', 4, 2024, '四川省', '巴中市', '巴州区', '新增街道', 0, 0, '2024-01-01 00:00:00', '2024-01-01 00:00:00');

INSERT INTO `grassroots_organization` (`county_id`, `parent_id`, `code`, `name`, `level`, `year`, `province_name`, `city_name`, `county_name`, `township_name`, `is_baseline`, `is_deleted`, `create_time`, `update_time`) VALUES
  (NULL, NULL, '511902009', '新增街道', 4, 2024, '四川省', '巴中市', '巴州区', '新增街道', 0, 0, '2024-01-01 00:00:00', '2024-01-01 00:00:00');
```

#### 2.2 删除数据（软删除）
```sql
-- 删除：511902010 - 已撤并街道
UPDATE `organization` SET `is_deleted` = 1 WHERE `code` = '511902010' AND `year` = 2024;
UPDATE `grassroots_organization` SET `is_deleted` = 1 WHERE `code` = '511902010' AND `year` = 2024;
```

#### 2.3 变更数据
```sql
-- 变更：511902011 - 旧街道名 -> 新街道名
UPDATE `organization` SET `name` = '新街道名', `township_name` = '新街道名', `update_time` = '2024-01-01 00:00:00' WHERE `code` = '511902011' AND `year` = 2024;
UPDATE `grassroots_organization` SET `name` = '新街道名', `township_name` = '新街道名', `update_time` = '2024-01-01 00:00:00' WHERE `code` = '511902011' AND `year` = 2024;
```

## 执行流程

### 直接导入流程
```
1. 读取 GeoJSON 文件
   ↓
2. 获取 2020 年基准数据（用于查找父级）
   ↓
3. 获取 2024 年已有数据（用于对比）
   ↓
4. 解析 GeoJSON 要素
   ↓
5. 对比生成变更（新增/删除/变更）
   ↓
6. 应用变更到 organization 表
   ↓
7. 应用变更到 grassroots_organization 表
   ↓
8. 返回导入结果
```

### SQL 脚本执行流程
```
1. 备份 2020 年基准数据（手动执行 mysqldump）
   ↓
2. 读取 GeoJSON 文件
   ↓
3. 获取 2020 年基准数据
   ↓
4. 获取 2024 年已有数据
   ↓
5. 解析 GeoJSON 要素
   ↓
6. 生成备份 SQL（2020 年数据 INSERT 语句）
   ↓
7. 生成变更 SQL（INSERT/UPDATE/DELETE）
   ↓
8. 保存 SQL 文件
   ↓
9. 手动执行 SQL 文件（mysql -u root -p < organization_2024_change.sql）
```

## 注意事项

1. **数据备份**：执行变更前请先备份数据库
2. **事务处理**：直接导入方式使用事务，SQL 脚本方式需要手动控制
3. **软删除**：删除操作使用软删除（`is_deleted=1`），不会物理删除记录
4. **年份隔离**：2024 年的数据与 2020 年基准数据相互独立
5. **父级关系**：根据行政区划代码自动推断父级（前 6 位为区县代码）
